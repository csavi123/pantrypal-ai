# PantryPal AI — project rules

Web app that suggests up to 3 healthy, protein-rich recipes from the user's pantry ingredients, cooking time, cuisine and dietary restrictions.

## Stack
- TanStack Start (React) + TypeScript + Tailwind (generated by Lovable). Do not add app server functions; all backend logic lives in the Supabase edge function
- Supabase: auth, Postgres with RLS, edge function `generate-recipes` (Deno)
- Synced to Lovable through GitHub on the main branch

## Do not touch
- Do not rename, move or rewrite src/integrations/supabase/* or the auth setup.
- Do not change the existing table names or column names.
- Never put API keys in frontend code. Secrets live in Supabase secrets: AI_PROVIDER, AI_API_KEY, USDA_API_KEY, DAILY_GENERATION_LIMIT.
- Database changes go in a new file in supabase/migrations/ and must be listed for me to apply.

## Hard product rules
- Never suggest a recipe that violates the user's dietary restrictions.
- Never claim an ingredient is in the pantry unless the user entered it. Anything else is listed as missing.
- Nutrition is always labeled as an estimate. If reference data is unavailable for an ingredient, say so; never invent numbers.
- Recipe generation retries at most 2 times (3 attempts total), then returns a clear message explaining which requirement could not be met.
- Never present the app as medical or dietetic advice.
- Max 5 generations per user per day (DAILY_GENERATION_LIMIT). Retries do not count as extra generations.

## Working style
- Small, focused changes. Explain what changed and how to test it.
- Run `npm run build` before saying a task is done, and fix any errors.
